# PyBroker applicability review

Reviewed 2026-10-04 against 37 public repositories returned for `user:0xtrvkc`. This is a backtesting-method applicability inventory, not a claim that every repository is free of bugs. Private repositories were not included. The existing four upgrades and these corrections are original browser-native implementations; none executes the Python PyBroker library.

The four existing merged PRs were verified: [EMA #7](https://github.com/0xtrvkc/btcEmaCrossBacktest/pull/7), [Prop #1](https://github.com/0xtrvkc/prop_challenge_simulator/pull/1), [Grid #1](https://github.com/0xtrvkc/btc-grid-sandbox/pull/1), [Options #1](https://github.com/0xtrvkc/btc-options-sandbox/pull/1). Their regression checks pass. DXY holdout input, post-mortem hourly gaps, and evidence gates are the remaining corrections proposed in separate repositories. MVRV desktop/mobile forecast functions already freeze halving-close information and exclude incomplete-cycle scores; this was a source review, not a complete runtime audit of those apps.

PyBroker's [documentation](https://www.pybroker.com/en/latest/index.html) describes a Python strategy engine. Its [bootstrap procedure](https://www.pybroker.com/en/latest/notebooks/3.%20Evaluating%20with%20Bootstrap%20Metrics.html) uses per-bar BCa metrics. Percentile block resampling in these browser apps is a different estimator. Adding the dependency to unrelated apps would not make their calculations more accurate.
